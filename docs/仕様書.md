# 配送管理システム 仕様書（現状実装まとめ）

最終更新: 2026-07-02（ブランチ: feature/system-settings 時点のコードを基に作成）

## 1. 概要

栃木県内の配送業務を対象とした配送計画・ルート最適化・配車管理・リアルタイム追跡を行う社内向けWebシステム。管理者・配送担当者がPCブラウザで配送計画を作成し、ドライバーはスマートフォンから専用URLで担当ルートを確認・進捗報告する。

## 2. 技術スタック

## 3. 認証・アクセス制御

- [src/lib/auth.ts](src/lib/auth.ts): NextAuthのCredentials認証。メール+パスワードで`User`テーブルを照合し、bcryptでパスワード検証。セッションはJWT方式、`role`（ADMIN/STAFF）をトークン・セッションに保持。
- [src/middleware.ts](src/middleware.ts): `/dashboard`, `/locations`, `/drivers`, `/trucks`, `/plans`, `/tracking` 配下を認証必須にするミドルウェア（未ログイン時は`/login`へリダイレクト）。
- `/driver/[routeId]` （ドライバー用ページ）はミドルウェア対象外＝ログイン不要。ルートIDを知っていれば誰でもアクセス可能なURL方式（配送計画詳細画面からコピーして共有する運用）。
- ロール（ADMIN/STAFF）はデータ上定義されているが、画面・APIレベルでの権限分岐は現時点で未実装（ログインさえできれば全機能利用可能）。
- シードデータで管理者アカウント `admin@example.com` / `admin1234` を作成（[prisma/seed.ts](prisma/seed.ts)）。

## 4. データモデル（[prisma/schema.prisma](prisma/schema.prisma)）

- **User**: 社内ユーザー（email, password, name, role: ADMIN/STAFF）
- **Truck**: トラック（plateNo, model, capacityKg, status: AVAILABLE/IN_USE/MAINTENANCE）
- **Driver**: ドライバー（name, phone, type: FIXED_ROUTE/REGULAR/SALES, licenseNo, status: ACTIVE/INACTIVE）
- **DriverDayOff**: ドライバーごとの平日休日設定（driverId, date）。土日・祝日はコード側でデフォルト休日扱いのためテーブルには保存しない。
- **Location**: 配送先マスタ（name, address, formattedAddress, phone, lat, lng, city）
- **DeliveryPlan**: 配送計画（planDate, status: DRAFT/CONFIRMED/IN_PROGRESS/COMPLETED, note, createdBy）
- **PlanRoute**: 配送計画内の1台分のルート（truckId, driverId, sortOrder, departureTime, status: PENDING/IN_PROGRESS/COMPLETED）
- **DeliveryStop**: ルート内の1停車地（locationId, stopOrder, scheduledTime, isTimeFixed, arrivedAt, status: PENDING/COMPLETED/SKIPPED, note）
- **SystemSetting**: システム全体の基本設定（シングルトン、id固定"default"）。デフォルト出発時間、昼休み時間帯、配送先ごとの標準積み下ろし時間、デフォルト荷量割合を保持。
- **TrackingLog**: ドライバーの位置情報履歴（routeId, lat, lng, timestamp）

## 5. 画面構成・機能一覧

### 5.1 ログイン（[/login](src/app/(auth)/login/page.tsx)）
- メールアドレス／パスワードでログイン。成功後 `/dashboard` へ遷移。

### 5.2 サイドバー ([Sidebar.tsx](src/components/ui/Sidebar.tsx))
- ナビ: ダッシュボード / 配送計画一覧 / 新規配送計画作成 / リアルタイム追跡
- マスタ管理セクション: 配送先管理 / ドライバー管理 / トラック管理 / システム設定
- ログアウトボタン

### 5.3 ダッシュボード（[/dashboard](src/app/(main)/dashboard/page.tsx)）
- 日付指定（デフォルト当日）でその日の状況を表示
- KPIカード（[KpiCards.tsx](src/components/dashboard/KpiCards.tsx)）: 当日計画数、完了数、進行中数、未割当トラック数/総トラック数
- ドライバー稼働状況テーブル（[DriverStatusTable.tsx](src/components/dashboard/DriverStatusTable.tsx)）: 全ドライバーの当日の状態（進行中/待機中/完了）と割当トラック
- 配送計画サマリ一覧（[PlanSummaryList.tsx](src/components/dashboard/PlanSummaryList.tsx)）: 各計画のルート数・停車数・完了数・配送先ステータス
- API: `GET /api/dashboard?date=YYYY-MM-DD`（過去7日分の完了件数集計も含む）

### 5.4 配送計画一覧（[/plans](src/app/(main)/plans/page.tsx)）
- 日付指定でその日の配送計画をガントチャート形式（配車表）で表示（[DispatchGanttChart.tsx](src/components/plans/DispatchGanttChart.tsx)）
- 「今日」「明日」「明後日」のラベル表示
- 各ルートをクリックすると該当の配送計画詳細画面へ遷移

### 5.5 新規配送計画作成（[/plans/new](src/app/(main)/plans/new/page.tsx)）
- 対象日を指定して計画を作成（DRAFT状態）→ 作成後、配送計画詳細画面（STEP1）へ遷移

### 5.6 配送計画詳細（[/plans/[id]](src/app/(main)/plans/[id]/page.tsx)）— STEP1/STEP2構成
共通:
- 計画ステータスバッジ表示（DRAFT/CONFIRMED/IN_PROGRESS/COMPLETED）
- 編集可否ポリシー（[planEditPolicy.ts](src/lib/planEditPolicy.ts)）: 進行中・完了状態、または対象日が「今日〜2日後」の範囲外の場合は編集不可。当日分は「same_day」警告を表示。
- DRAFT状態のみ計画削除が可能
- IN_PROGRESS状態の計画には「配送先の追加（稼働中の計画への追加）」パネルが表示され、既存の配達済み/スキップ済み停車地はそのまま、未配達分＋追加分のみ現在地（最新位置情報→直近配達地点→車庫の順）から再最適化できる（`POST /api/plans/[id]/routes/[routeId]/add-stops`）

STEP1（計画・ルート編集）:
- 対象日・出発時間の入力
- トラック・ドライバーの割当（現状UIは1組のみ。選択と同時に `POST /api/plans/[id]/check-assignment` で即時に同日重複チェック・休日チェックを実施）
- 配送先選択（検索・チェックボックス）。到着希望時刻を個別に入力可能（時刻指定した配送先は最優先でルートに組み込まれる）
- 選択中配送先の地図プレビュー（Leaflet）、地図クリックでも選択トグル可能
- 「ルート最適化して確認へ」: `POST /api/plans/[id]/optimize` を呼び、既存ルートがあれば上書き確認ダイアログを出した上で再生成。成功後 自動的にSTEP2へ遷移
- 「ルート変更せずに確認へ」: 既に生成済みのルートをそのまま保持して `PATCH /api/plans/[id]/routes` で保存し、STEP2へ遷移
- 到着希望時刻に間に合わない可能性がある場合はアラートで警告表示

STEP2（確認・確定）:
- ルート一覧テーブル（トラック・ドライバー・停車件数・ドライバー用URLコピー機能）
- 各ルートの出発・到着予定時刻の参照表示（時刻指定停車地は赤枠で強調）
- 配車表（ガントチャート）表示
- 「下書きとして保存」（DRAFT）または「計画を確定する」（CONFIRMED）でステータス変更 → 一覧画面へ遷移

### 5.7 リアルタイム追跡（[/tracking](src/app/(main)/tracking/page.tsx)）
- 当日の全ルートを一覧表示（15秒ごとにポーリング）、ルートごとのステータス・完了/全停車数
- ルート選択で停車地一覧（訪問状況）を表示
- 地図上にトラック位置・ルートを表示（[TrackingMap.tsx](src/components/map/TrackingMap.tsx)）、トラッククリックでルート選択と連動

### 5.8 ドライバー用画面（[/driver/[routeId]](src/app/driver/[routeId]/page.tsx)）
- ログイン不要、ルートID付きURLで直接アクセス（配送計画詳細画面からコピー配布）
- ヘッダーに車両ナンバー・計画ステータス・進捗バー
- 停車地カード一覧: 到着予定時刻（時刻指定/目安を区別表示）、住所、電話（タップで発信）、Googleマップ経路リンク
- 各停車地を「完了」「スキップ」「取消」で更新（`PATCH /api/tracking/stops/[id]`）
- 「運送開始」ボタンでルートステータスをIN_PROGRESSに変更
- 「位置情報の共有を開始/停止」: `navigator.geolocation.watchPosition` で位置情報を取得し `POST /api/tracking` へ送信。初回送信時に自動でルート・計画をIN_PROGRESSへ、全停車地が完了/スキップになると自動でCOMPLETEDへ遷移
- 位置情報送信・停車地更新はSocket.io（`tracking:update`, `tracking:stop-update`）でリアルタイム配信

### 5.9 配送先管理（[/locations](src/app/(main)/locations/page.tsx)）
- 新規登録フォーム（名称・住所・電話番号）。「住所確認」ボタンでジオコーディング結果（緯度経度・整形済み住所）をプレビュー表示してから登録
- 登録時はGoogle Geocoding APIで自動的に緯度経度を取得
- CSV一括登録（name, address, phone列）。行ごとに成功/失敗を判定し、失敗理由を一覧表示
- 地図プレビュー、名称・住所での検索、一覧テーブル表示

### 5.10 ドライバー管理（[/drivers](src/app/(main)/drivers/page.tsx)、[/drivers/[id]](src/app/(main)/drivers/[id]/page.tsx)）
- 種別タブ（固定ルート/専任/営業）ごとの一覧表示
- 新規登録（名称・電話番号・免許番号・種別）
- 休日設定画面: 月表示カレンダーで土日・祝日は自動的に休日（変更不可）、それ以外の平日をクリックして個別に休日を設定・保存

### 5.11 トラック管理（[/trucks](src/app/(main)/trucks/page.tsx)）
- 新規登録・編集（ナンバー・型式・積載量kg・ステータス: 使用可能/使用中/整備中）
- 一覧テーブルからインライン編集

### 5.12 システム設定（[/settings](src/app/(main)/settings/page.tsx)）
- デフォルト出発時間、昼休み時間帯（開始/終了）、配送先での標準積み下ろし時間（分）、デフォルト荷量割合（%）を設定
- ルート最適化・到着時刻推定計算のデフォルト値として使用される

## 6. ルート最適化ロジック（[src/lib/routeOptimizer.ts](src/lib/routeOptimizer.ts)）

- 拠点座標は栃木県庁付近に固定（`TOCHIGI_DEPOT`）
- **クラスタリング**: 選択された配送先を、割り当てたトラック台数 `k` でk-means風のクラスタリング（`clusterLocations`）により分割
- **順序付け**: 各クラスタ内で `orderWithTimeBudget` により順序を決定
  - 到着希望時刻（`arrivalTime`）が指定された停車地を「アンカー」とし、時刻の早い順に並べる
  - アンカー間の移動時間の余裕がある限り、現在地から近く・かつ間に合う時刻未指定の停車地を挿入
  - 余裕がなくなった時点で挿入を打ち切り、残りは次のアンカー区間または最後に最近傍法（`nearestNeighborOrder`）で配置
  - 昼休み時間帯（`lunchBreak`）にかかる場合は休憩明けまで繰り下げ
- **到着時刻推定**（`estimateStopTimes`）: 出発時刻から直線距離（ハーバサイン公式）÷平均速度30km/hで移動時間を積算し、各停車地の到着予定時刻を算出。設定された積み下ろし時間（デフォルト10分）を停車ごとに加算。到着希望時刻に対して移動時間的に間に合わない場合は `timeConflict` フラグを立てて警告メッセージを生成
- 1ルートあたりの最大停車地数は40件（`MAX_STOPS_PER_ROUTE`）、トラックは最大15台まで指定可能
- 稼働中の計画への配送先追加時（`add-stops` API）は、拠点ではなく現在地（最新位置情報 > 直近配達地点 > 拠点の順）を起点に、未配達分＋追加分のみ再計算

## 7. バリデーション・整合性チェック（[src/lib/planValidation.ts](src/lib/planValidation.ts)）

- `checkTruckAvailable` / `checkDriverAvailable`: 同一日に同じトラック・ドライバーが他の計画で既に割り当てられていないか確認
- `checkDriverNotOnDayOff`: 対象日がドライバーの休日（土日祝日 or 個別設定日）でないか確認
- 配送計画の編集可否は [planEditPolicy.ts](src/lib/planEditPolicy.ts) の `canEditPlan` / `getEditWarning` で判定（進行中・完了は不可、当日〜2日後のみ編集可能、当日編集時は警告表示）

## 9. リアルタイム通信

- カスタムサーバー（[server.ts](server.ts)）でSocket.ioを `/api/socket` パスで稼働
- イベント: `tracking:update`（位置情報更新）、`tracking:stop-update`（停車地ステータス更新）をサーバーからemit
- 現状、クライアント側（[/tracking](src/app/(main)/tracking/page.tsx)画面）はSocket.io購読ではなく15秒ポーリングで実装されている（Socket.ioサーバー側の配信基盤は存在するが、追跡画面でのリアルタイム受信は未接続）
